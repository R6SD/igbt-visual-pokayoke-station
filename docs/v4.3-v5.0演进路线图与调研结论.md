## 1. 执行摘要与核心定论

面向 IGBT 透明料管 720P @ 25 FPS 产线防呆工位，四维调研形成如下核心工程定论：

1. **视觉算法升级（单帧预算 ≤ 15ms）**：
   - 放弃整管 `minAreaRect`，改用**中段有效带 RANSAC 平行双边线拟合 + 低自由度仿射/单应透视拉平**，配合 4 项几何完整性门控（条件数 $\kappa \le 3.5$、平行度 $\Delta\theta \le 3.0^\circ$ 等）与 `TUBE_ALIGN_FAIL` 安全阻断；
   - 以 **NanoDet-Plus-m（`320×320`，FP32 ONNX，4.5–8.5 ms）** 替换 HSV/YCrCb 启发式实现 `bare_hand` / `esd_white` / `esd_gray` / `esd_black` 四分类，并引入**非对称滞回防抖**（2 帧快触发、10 帧慢解除）；
   - 标签分类采用 **MobileNetV3-Small / ShuffleNetV2-0.5x（FP32 ONNX，1.8–3.2 ms）** 单次前向双输出 `logits` 与 `penultimate_feat`，结合 **Temperature Scaling + Energy Score + Mahalanobis 距离双门控**拒识未知 OOD 异常。
2. **半导体封测产线防呆闭环（OSAT / AEC-Q101）**：
   - 落地 **Red Rabbit（红兔/金样）强制挑战状态机**（换班/周期/换批/冷启与故障恢复 4 类不可跳过触发 + OK/NG 随机序列 + 唯一 `sample_uid` 扫码防作弊 + SHA-256 哈希链审计表）；
   - 采用 **原生 Winsock2 轻量 Modbus TCP 客户端**对接研华 `ADAM-6050/6060` 写入 `industrial_hal.hpp`，实施**正逻辑使能 + 常闭（NC）失电安全**与 EEPROM 硬件 Watchdog，实现进程卡死/断网 2.5s 内物理落锁；
   - MES 防混料采用 **SQLite 事务性发件箱（Transactional Outbox）+ `X-Idempotency-Key`**，车规级默认 **Fail-Closed**，常规产线经 QA 审批可开受控白名单（≤50 管且 ≤30 分钟）。
3. **架构治理与 MSYS2 UCRT64 质量门禁**：
   - 按**绞杀者模式（Strangler Fig）**分阶段拆解 5 个巨石文件（合计 >17,000 行），保留原头文件/HTTP/SQLite 契约；
   - **关键环境避坑**：MSYS2 UCRT64 `g++ 15` 缺乏原生 `-fsanitize=address` 运行时支持，即便切换到 `CLANG64` 启用实验性 ASan 也易与预编译 OpenCV DLL / DirectShow COM 产生 CRT 堆拦截冲突；因此测试金字塔采用 **`clang-tidy` + `cppcheck` 静态门禁 + Windows `PageHeap / Application Verifier` + 黄金帧回放 CTest + 前端 `Vitest / Playwright`**。
4. **Top 3 P0 落地建议**：
   - **P0-1（v4.3）**：`ADAM-6050/6060` 硬件看门狗与断电安全闭锁（`industrial_hal.hpp` 驱动落地）；
   - **P0-2（v4.3）**：Red Rabbit 红兔强制挑战点检状态机 + SHA-256 哈希链审计 + HMI 全屏不可关闭挑战遮罩；
   - **P0-3（v4.4）**：NanoDet-Plus-m 手套/裸手检测 + 料管中段 RANSAC 透视拉平与 `TUBE_ALIGN_FAIL` 安全回退。

## 2. 维度一：纯 C++20 + OpenCV 4 DNN 视觉算法升级

在 `1280×720 @ 25 FPS`（单帧周期 `40 ms`）下，视觉推理链必须控制在 **≤ 15 ms/帧**，为 DirectShow 采集、MJPEG 推流、`async_evidence_writer` 异步落盘与 Windows 线程调度抖动留足 **≥ 25 ms** 余量。

### 2.1 单帧 15ms CPU 预算分配（典型 x86_64 AVX2 工控机，i5-12400 / i7-12700 4 线程）

| 流水线阶段 | 实现方案 | 目标耗时区间 |
| --- | --- | --- |
| 1. 预处理 + 高光掩膜 | `640×360` 缩放 + `V ≥ 250, S ≤ 15` 镜面高光剥离 | `~1.0 ms` |
| 2. 手部/手套检测 | `NanoDet-Plus-m`（`320×320` FP32 ONNX，全帧或隔 2 帧步进均摊） | `3.5 – 6.5 ms` |
| 3. 料管中段拉平 + 180° 校验 | 掩膜去手 + CLAHE + 定向 Sobel + RANSAC 平行边 + `warpPerspective` | `2.0 – 3.2 ms` |
| 4. 标签分类 + OOD 双门控 | `MobileNetV3-Small`（`224×64` FP32 ONNX）+ Energy + Mahalanobis | `1.8 – 3.2 ms` |
| **合计** | **全链路端到端 CPU 耗时** | **`9.5 – 12.5 ms`（≤ 15 ms 红线）** |

> **低功耗平台不确定性说明**：若产线工控机为 **Celeron J6412 / N97** 等无高主频 AVX2 平台，纯 CPU 推理耗时通常会放大 **2.5×–3.5×**，此时必须启用检测隔帧调度（每 2 帧运行 1 次 NanoDet + 帧间 IOU/光流框外推或变化触发区推理），才能守住 15ms 红线。

### 2.2 透明料管透视拉平（中段 RANSAC + 失败安全回退）

- **现状痛点**：双端 ESD 手套握持会遮挡料管真实端点，直接对全管轮廓求 `minAreaRect` 会导致长轴畸变与主轴角漂移；同时强反光伪边缘和低对比度壁面易导致普通 Canny 断裂。
- **鲁棒拉平 4 步流水线（2.0–3.2 ms）**：
  1. **中段掩膜隔离**：降采样至 `640×360`，叠加坡璃高光掩膜（`V ≥ 250, S ≤ 15`）与手部检测框膨胀掩膜，仅保留双端手套之间的**中段 40%–65% 有效管身带**。
  2. **定向梯度增强**：对中段灰度 ROI 做局部 CLAHE（`clipLimit = 2.0`），计算垂直于预期进料方向的 `Sobel(dx=0, dy=1)`（在料管倾角 `±25°` 内可有效压制管内金属引脚的垂直纹路干扰）。
  3. **RANSAC 平行双边线拟合**：`cv::HoughLinesP` 提取候选线段并按倾角（`±25°`）聚类，通过 RANSAC 搜索满足料管标定像素宽度先验 $W_{\text{tube}} \in [W_{\min}, W_{\max}]$ 的上下平行壁面直线对 $(L_{\text{top}}, L_{\text{bot}})$。
  4. **虚拟角点低自由度映射**：沿拟合中轴在 $[-L/2, +L/2]$ 截取上下壁面 4 个虚拟角点（避开被手遮挡的真实管端）。光轴倾角 $< 5^\circ$ 时优先用 `cv::estimateAffinePartial2D` 刚体约束仿射；存在明显俯仰透视时再以 `cv::getPerspectiveTransform` 计算 $3\times 3$ 单应矩阵 $H$ 并 `cv::warpPerspective` 输出标准 ROI（如 `256×64`），直接复接现有“首尾灰度不对称防 180° 掉包”校验。
- **几何完整性门控（4 项硬校验）**：
  - 矩阵条件数：左上 $2\times 2$ 仿射子阵奇异值比 $\kappa = \sigma_{\max} / \sigma_{\min} \le 3.5$，且行列式 $\det(H_{2\times 2}) \in [0.25, 4.0]$；
  - 平行度与管宽：上下壁夹角差 $\Delta\theta \le 3.0^\circ$，中段实测管宽偏差在标定值的 `±12%` 以内；
  - 帧间阻尼：正常工况对中心 $(c_x, c_y)$ 与倾角 $\theta$ 施加 EMA 平滑（$\alpha = 0.6$），单帧角跳变 $> 15^\circ$ 判为异常干扰；
  - **宁拒不放行回退策略**：
    - 连续失败 $\le 2$ 帧：复用上一有效矩阵 $H_{t-1}$ 并标记低置信度（允许维持状态，**禁止推进 1.2s PASS 达标计时**）；
    - 连续失败 $\ge 3$ 帧或几何门控越界：置状态 `TUBE_ALIGN_FAIL`，**严禁静默回退到无拉平全图分类**，立即阻断 PASS 计时并上报对齐告警。

### 2.3 轻量 ONNX 分类 + OOD 未知异常拒识（纯 `cv::dnn` CPU）

- **推理格式约束**：OpenCV 4 `cv::dnn` 在 x86 CPU（AVX2）下对 **FP32 ONNX** 支持最稳；INT8 QDQ 量化 ONNX 在 `cv::dnn` 易发生算子回退导致反比 FP32 更慢。推荐导出 **FP32 ONNX** 的 `MobileNetV3-Small` 或 `ShuffleNetV2-0.5x`（输入 `224×64` 或 `128×64`，单次推理 `1.8–3.2 ms`），输出 4 类已知态：`INTACT_WHITE`、`A_SCRATCHED`、`B_OCCLUDED`、`C_DETACHED`。
- **单次前向双张量提取（零额外推理耗时）**：
  ```cpp
  std::vector<cv::Mat> outputs;
  net.setInput(blob);
  net.forward(outputs, {"logits", "penultimate_feat"});
  ```
- **OOD 数学公式与标定**：
  1. **Temperature Scaling**（离线在 ID 验证集最小化 NLL 求标量 $T > 0$）：
     $$p_i(x) = \frac{\exp(z_i / T)}{\sum_{j=1}^{K} \exp(z_j / T)}$$
  2. **Energy Score**（主力 OOD 指标，C++ 必须用 LogSumExp 防上溢，令 $m = \max_j (z_j / T)$）：
     $$E(x) = -T \cdot \left( m + \log \sum_{j=1}^{K} \exp\left(\frac{z_j}{T} - m\right) \right)$$
     *判别特征*：ID 样本能量更低（负值更大），OOD 样本（异色标签、空管、异物遮挡、强过曝）能量升高。
  3. **Mahalanobis Distance**（特征空间正交补充，防高 logit 盲区；$d=256$ 时耗时 $< 0.15\text{ ms}$）：
     离线基于 ID 训练集计算各类特征均值 $\mu_c \in \mathbb{R}^d$ 及 Tikhonov 正则共享协方差逆矩阵 $\Sigma_{\text{reg}}^{-1} = (\Sigma + \lambda I)^{-1}$（$\lambda \approx 10^{-3}$）：
     $$D_M(x) = \min_{c \in \{1 \dots K\}} \sqrt{(\phi(x) - \mu_c)^T \Sigma_{\text{reg}}^{-1} (\phi(x) - \mu_c)}$$
     *轻量替代（Cosine-Margin）*：若采用 L2 归一化余弦分类头，可用 $s_{\max}(x) = \max_c \frac{\phi(x)^T w_c}{\|\phi(x)\|_2 \|w_c\|_2}$ 替代马氏距离，省去 $\Sigma_{\text{reg}}^{-1}$ 存储。
- **双门控阈值标定与安全回退**：
  - 在含正常波动（光照 `±15%`、轻微位移）的 ID 验证集取 $E(x)$ 与 $D_M(x)$ 的 **98%–99% 分位数**作为初值 $\tau_E, \tau_M$，并用负样本集校验 `AUROC >= 0.95`、`FPR@95TPR <= 5%`；所有参数及 $\mu_c, \Sigma_{\text{reg}}^{-1}$ 固化至与 `.onnx` 绑定的 `ood_calibration.json`（含 SHA-256 校验）。
  - **运行时门控**：仅当同时满足 $\max_i p_i(x) \ge \tau_p$（如 `0.85`）、$E(x) \le \tau_E$ 且 $D_M(x) \le \tau_M$ 时提交分类结果给 `fsm.cpp`；任一越界即判 `STATE_OOD_UNKNOWN`，冻结 1.2s PASS 累计；连续 5 帧 OOD 直接触发 `ALARM` 并由 `async_evidence_writer` 连拍落盘供 `training_manager` 增量迭代。

### 2.4 超轻量 ONNX 手部/手套检测选型与 ESD 防误报

| 模型架构 | 输入分辨率 | 参数量 | x86 AVX2 CPU 耗时* | OpenCV DNN 兼容性 | 场景适配结论 |
| --- | --- | --- | --- | --- | --- |
| **NanoDet-Plus-m** | `320×320` | ~1.17M | **4.5 – 8.5 ms** | 极佳（纯 Conv/DWConv） | **首选**：Anchor-free + GFL 头，遮挡手部定位稳、后处理极简 |
| **YOLOv8n** | `320×320` / `640×640` | ~3.2M | `6–12ms` / `22–42ms` | 良好（需自定义 NMS） | 备选（仅限 `320`；`640` 必爆 15ms 预算） |
| **YOLOv11n** | `320×320` / `640×640` | ~2.6M | `7–13ms` / `25–45ms` | 需 OpenCV ≥ 4.10 | 不推荐：C2PSA 注意力块在纯 CPU 访存开销高 |
| **MobileNetV3-SSDLite** | `320×320` | ~2.5M | `5.5 – 10.5 ms` | 中等（Reshape 易报错） | 不推荐：握持姿态下手指框回归逊于 NanoDet-Plus |
| **MediaPipe Palm** | `192×192` | ~1.0M | `2.5 – 4.5 ms` | 差（TFLite 算子转换坑） | **淘汰**：偏裸手掌，黑/灰 ESD 手套及侧面握持漏检率极高 |

- **ESD 白/灰/黑手套与裸手防误报实践**：
  - 训练 NanoDet-Plus-m 直出 4 类：`bare_hand`、`esd_white`、`esd_gray`、`esd_black`，避免级联检测延迟；
  - **高风险混淆物理护栏**：① 判为 `esd_white` 时校验框内过曝占比（`V >= 245` 超过 `35%` 视为照明异常告警）并复核腕部过渡区 YCrCb 肤色连通域；② 以料管中心线几何掩膜硬隔离标签区与两侧握持区，防止白手套与白标签粘连；③ 对低亮度 `esd_black` 区域（`V <= 45`）结合高频碳纤维纹理梯度辅助区分手套与桌面阴影；
  - **非对称滞回防抖**：保持 `0.22 <= cy <= 0.88` 操作区门控，裸手改为**快触发、慢解除**——连续 **2 帧**检出 `bare_hand`（置信度 `>= 0.60`）即刻闭锁 `ALARM`；解除闭锁需连续 **10 帧**确认无裸手且满足复位条件，杜绝“快速闪手”逃逸。

## 3. 维度二：半导体封测产线防呆闭环（OSAT / AEC-Q101）

### 3.1 Red Rabbit（红兔/金样强制挑战点检）状态机与 SQLite 审计 Schema

- **4 类不可跳过强制触发条件**：
  1. 换班定时（白/夜班切换如 `08:00` / `20:00`，可配 `0–10 min` 宽限期，超时强锁）；
  2. 固定周期（距上次合格点检超 `4h` / `8h`）；
  3. 换批/换型（MES 切换工单、`Lot ID` 或器件封装配方）；
  4. 异常重启/变更（冷启动、`Minidump` 崩溃恢复、相机重连、光学 3A 重标定或 ONNX 模型版本切换）。
- **状态机流转（集成至 `cpp_backend/src/fsm.cpp`）**：
  - `PROD_READY` $\xrightarrow{\text{触发}}$ `CHALLENGE_REQUIRED`（拉低 HAL 放行 DO，前端弹出全屏不可关闭挑战遮罩）；
  - 系统从金样库随机生成打乱序列，要求投入至少 **1 支 OK 金样 + ≥ 2 支典型 NG 金样**（如未划除白标、半划除、180° 倒置管、可选 OOD 异常管），且**每支必须先扫码/录入唯一 `sample_uid` 再进视场判定**，防止重复拿同一支管刷点检；
  - 全部匹配 $\rightarrow$ 写审计表并恢复 `PROD_READY`；任一误判（尤其 NG 误判 PASS）或超时 $\rightarrow$ 切入 `CHALLENGE_HARD_LOCK`，触发声光闭锁与连拍取证，**仅 Engineer / QE 登录填写根因与解锁说明后可回到 `CHALLENGE_REQUIRED` 重新完整挑战**（禁止跳过直接量产）。

### 3.2 Modbus TCP / Advantech ADAM-6050/6060 故障安全心跳（Fail-Safe Watchdog）

- **电气断电安全（Fail-Safe）铁律**：采用**正逻辑使能 + 常闭报警（NC）**——放行/健康 DO 采用高电平有效（`DO = 1` 表示系统健康允许放行）驱动安全继电器线圈；报警灯塔与治具挡停电磁阀接常闭/失电落锁回路。工装调试阶段用研华工具将 ADAM 内置 **Host Communication Watchdog** 固化进 EEPROM（超时 `2000–3000 ms`，`DO Safety Value = 0`），确保工控机蓝屏/断网/进程崩溃 2.5s 内硬件自动物理落锁。
- **Winsock2 原生 vs `libmodbus` 选型定论**：Windows MSYS2 UCRT64 下推荐**原生 Winsock2 封装轻量 `ModbusTcpClient`（~300 行 C++20）**实现 `cpp_backend/include/igbt/industrial_hal.hpp`：
  - 零外部 MinGW DLL 打包与 ABI 漂移风险，Modbus TCP 线圈读写（FC01/02/05/15）协议简单可控；
  - 通过非阻塞 Socket + `WSAPoll` 严格限制 `Connect <= 500ms`、`Send/Recv <= 200ms`，避免阻塞 Socket 断线卡死 21 秒拖垮看门狗；
  - 校验 MBAP `Transaction ID` 匹配，并由 `std::chrono::steady_clock` 统计连续超时。
- **与主循环及 FSM 联动要点**：
  - 独立 `std::jthread` 每 `500ms` 执行：① FC15 写心跳/安全 DO（同时刷新 ADAM WDT）；② FC02 回读 DI（急停按钮、光电到位、继电器辅助触点——用于检测触点粘连）；
  - 校验视觉主线程更新的 `std::atomic<int64_t> last_vision_tick_ms`，若视觉线程假死 `> 1000ms`，心跳线程主动停喂并拉低 DO（**软死锁 → 硬落锁**）；
  - 连续 2 次通信超时（`>= 1000ms`）回调通知 `fsm.cpp` 进入 `HARDWARE_FAULT_LOCK`；注：不同固件版本 WDT 私有保持寄存器地址可能存在差异，建议在 `hal_adam.json` 参数化线圈基址（标准 DI `0x0000`、DO `0x0010`），WDT 参数预先固化进模块 EEPROM。

### 3.3 MES 工单/批次防混料校验幂等性与断网降级

- **批次绑定与幂等键**：每次检出 `PASS`/`ALARM` 绑定当前 `work_order`、`lot_id`、`device_part_no`、`model_sha256`，生成确定性幂等键：
  $$\text{idem\_key} = \text{SHA256}(\text{station\_id} \mid \text{lot\_id} \mid \text{event\_uuid} \mid \text{tube\_seq})$$
  同时经 HTTP Header `X-Idempotency-Key` 与 JSON `event_id` 双重透传给 MES，避免超时重试引起重复过站或计数漂移。
- **SQLite 事务性发件箱（Transactional Outbox）**：检测记录与 MES 待发任务必须在**同一个 SQLite 事务**内提交。

```sql
CREATE TABLE IF NOT EXISTS mes_outbox_queue (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    idempotency_key  TEXT NOT NULL UNIQUE,
    endpoint_path    TEXT NOT NULL,
    payload_json     TEXT NOT NULL,
    status           TEXT NOT NULL CHECK (status IN ('PENDING','IN_FLIGHT','ACKED','DEAD_LETTER')),
    retry_count      INTEGER NOT NULL DEFAULT 0,
    next_retry_at_ms INTEGER NOT NULL,
    last_http_code   INTEGER,
    last_error       TEXT,
    created_at_ms    INTEGER NOT NULL,
    acked_at_ms      INTEGER
);
CREATE INDEX IF NOT EXISTS idx_mes_outbox_sched ON mes_outbox_queue(status, next_retry_at_ms);
```

- **断网降级双模式**：

| 策略维度 | 车规/AEC-Q101 严苛模式（**默认 Fail-Closed**） | 常规工业受控白名单模式（须 QA 审批开启） |
| --- | --- | --- |
| **网络心跳超时** | 连续失败 `> 60s` 锁定工位，禁止新检测 `PASS` | 仅允许**断网前已在线校验签名的当前活跃 Lot** 继续作业 |
| **换批/换工单** | **严格禁止** | **严格禁止**（离线无法核验新批次防混料） |
| **离线配额上限** | `0` 管（或仅完成已开始的第 1 管） | 双重硬上限：离线数量 `<= 50` 管 **且** 离线时长 `<= 30 min`，先到先锁 |
| **恢复补传对账** | 恢复后 FIFO 补传未确认收尾记录 | 按 `id` 指数退避补传；若 MES 返回 Lot 已 `Hold/Scrap`，立即触发追回弹窗告警并锁机 |

### 4.2 Windows MSYS2 UCRT64 + React/Vite 低开销测试金字塔

- **MSYS2 UCRT64 GCC 15 的 ASan 限制核实**：MinGW-w64 GCC 在 Windows 下缺乏完整的 PE `libasan` 运行时支持，直接加 `-fsanitize=address` 会链接失败；即便切换 `MSYS2 CLANG64` 开启实验性 ASan，也极易与预编译 OpenCV DLL、DirectShow COM 钩子及 Windows 系统 DLL 产生 CRT/堆拦截冲突。
- **100% 兼容 UCRT64 的务实质量门禁**：
  1. **静态分析门禁（每次提交，`< 20s`）**：CMake 导出 `compile_commands.json`，运行 MSYS2 原生 `clang-tidy`（`bugprone-*`、`clang-analyzer-*`、`concurrency-*`、`modernize-use-nullptr`）+ `cppcheck`，编译器渐进开启 `-Wall -Wextra -Wshadow -Werror=return-type`。

  3. **黄金帧回放测试（Golden Frame Replay，CTest 核心防线）**：在 `cpp_backend/tests/test_cpp_station.cpp` 注入与 DirectShow 同源的虚拟相机帧供给接口，回放 10–15 组产线切片（正常 PASS、强反光、A/B/C 标、180° 倒置、三色 ESD 手套、裸手闪入、OOD 异型管），硬性断言：**漏检 `FN = 0`、单帧 P95 `<= 15ms`、红兔与断网状态机转移 100% 吻合**。
  4. **前端金字塔（React 19 + Vite 8）**：
     - 静态门禁：`tsc -b` + `eslint --max-warnings 0` + 样式字号/字重规则校验；

## 6. 风险、不确定性与纯软件无法替代的物理边界

以下 5 类失效属于物理信息丢失或硬件安全边界，**任何算法或软件架构升级都无法实现 100% 软件兜底**，必须在推进各阶段前同步锁定光学/工装与电气前提：

1. **无偏振镜面饱和反光**：当透明料管表面形成大面积 `RGB=(255,255,255)` 饱和高光且覆盖划除区时，像素细节已物理丢失，软件剥离高光掩膜只能做到“拒识报警”，无法还原被遮盖的划痕。**前提**：加装光源偏振膜 + 镜头线偏振滤镜（CPL）双向正交偏振与低角度漫射光。
2. **浅肤色裸手过曝与白色 ESD 手套同色冲突**：在未控顶光下，浅肤色手背高光区与白色尼龙手套色度高度重叠，强行提召回率会引发高频误停线。**前提**：统一使用深灰/蓝/黑 ESD 手套，并配合非黑非白的哑光中灰/哑光蓝绿工装台面。
3. **720P 滚动快门运动模糊与低对比度景深**：作业员快速挥管通过消费级 Rolling Shutter 摄像头时，单帧拖影会导致划痕断裂及 180° 特征失效。**前提**：强制操作停顿节拍 `>= 1.2s`、恒定补光下压缩短曝光（`<= 4ms`），有条件时升级全局快门（Global Shutter）工业相机。
4. **单顶视物理遮挡与盲区**：单顶视相机无法识别贴在料管侧面/背面的漏划标签，也无法穿透手套检测被手掌完全覆盖的缺陷。**前提**：作业台面加装 V 型定位限位槽 + 物理视觉基准框，规范标签朝上与双端握持区。
5. **软件看门狗无法替代电气/机械本质安全**：若仅靠前端弹窗或无物理执行机构的软告警，作业员仍可能无视红灯将 NG 管投入良品箱。**前提**：必须经 `ADAM-6050/6060` + 安全继电器联动声光柱与良品通道气动挡板/扫码门禁互锁，达成“未 PASS 物理进不去良品箱”。
